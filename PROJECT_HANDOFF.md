# Gourmeta

## Запуск из папки site

Скопируй папку `site` целиком. В ней находятся WordPress, медиа, настройки Docker, снимок базы и материалы фирменного стиля. На новом устройстве запусти Docker с Linux-контейнерами и выполни команду из папки `site`.

```sh
docker compose up -d --wait
```

Сайт откроется на <http://127.0.0.1:8187/>, админка на <http://127.0.0.1:8187/wp-admin/>. Данные входа в локальную админку хранятся в `local/secrets/wp-admin-username.txt` и `local/secrets/wp-admin-password.txt`. Для запуска нужен свободный порт `8187`.

При первом запуске MariaDB создаёт том `gourmeta-local_database` и импортирует `local/database/gourmeta.sql`. При повторном запуске сайт использует данные существующего тома. Если на новом устройстве уже есть одноимённый том Gourmeta, автоматический импорт в него пропускается.

## Перенос после дальнейших правок

Пока Docker-проект запущен, выполни команду обновления дампа из папки `site`.

```sh
docker compose exec -T db sh /usr/local/bin/gourmeta-export-db
```

После сообщения `Updated local/database/gourmeta.sql` скопируй папку `site` целиком. Команда заменяет снимок после успешного экспорта и проверки файла. Дамп и локальные реквизиты находятся вне веб-корня и исключены из Git. Для переноса используй приватную копию папки.

Остановить проект можно командой `docker compose stop`.

## Исходники на GitHub

Приватный репозиторий [Renat1144/gourmeta](https://github.com/Renat1144/gourmeta) содержит код, ресурсы темы и локальные Docker-настройки. База, медиатека WordPress, документы бренда, ролик старого шаблона, файлы подтверждения домена и реквизиты остаются в приватной локальной копии. Для чистого клона смотри [README.md](README.md). Два последовательных запуска `prepare` проверены в отдельной рабочей папке. Команда создаёт локальные файлы по шаблону и сохраняет уже существующие данные.

## Состояние на 20 ноября 2026 года

- Рабочий корень WordPress находится в `gourmeta.ru/docs`. Активны тема Gourmeta и 10 плагинов. В `wp-content/uploads` сохранены 609 файлов. Материалы для будущего дизайна находятся в `references/`.
- `compose.yaml` запускает PHP 8.3 с Apache и MariaDB 11.4. PHP-конфиг в веб-корне использует локальную БД и реквизиты из `local/secrets`. Хостинговые настройки сохранены в папке восстановления.
- Из рабочего дерева вынесены старые снимки 2017 и 2025 годов, дубли выгрузок 2022 года, служебные папки хостинга, логи, неактивные стандартные темы и плагины из комплекта WordPress. Файлы плагинов резервного копирования и переноса входят в рабочую копию. На исходном компьютере вынесенные материалы находятся в `../site-recovery-2026-11-20` с исходной структурой путей. Исходная выгрузка базы хостинга хранится рядом с папкой `site`.
- Снимок содержит 31 таблицу. Проверен импорт в пустую изолированную MariaDB, совпали контрольные данные записей, настройки сайта и хеш локального администратора. Сайт проверен в браузере, для страниц каталога, формы и ресурсов получен HTTP 200. В исходной локальной среде проверен вход и открытие редактора главной.
- В теме действует исправление PHP 8 для формирования ссылок оборудования. Исходный файл темы хранится в папке восстановления. Старая ссылка на Cafitesse Quantum 120 возвращает 404. Её назначение нужно сверить с текущим каталогом при модернизации.
- В локальной среде отключены автоматические обновления, WP-Cron и внешние запросы через HTTP API WordPress в `gourmeta.ru/docs/wp-config.php`, отправка почты через PHP отключена в `local/php.ini`. Веб-сервер слушает только `127.0.0.1`. Файлы хостинга и резервные копии сохранены отдельно.
